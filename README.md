# MoodMapper — Спецификация

**Аспектный анализ тональности русскоязычных отзывов**

---

## 1. Назначение системы

MoodMapper — веб-приложение для аспектного анализа тональности (ABSA, Aspect-Based Sentiment Analysis) русскоязычных текстов. Система принимает текст отзыва и определяет тональность **каждого аспекта** (сущности) в нём отдельно, а не общую тональность текста.

**Пример:**
- Вход: `"Пицца была вкусной, но доставка опоздала на час"`
- Выход:
  - `пицца → ПОЗИТИВ`
  - `доставка → НЕГАТИВ`

**Ключевое требование:** вся обработка происходит **на стороне клиента** (в браузере), без серверной части.

## 2. Функциональные требования

### 2.1. Два режима работы

| Режим | Вход | Выход |
|-------|------|-------|
| **Одиночный** | Текст отзыва (textarea) | Карточки аспектов + сводка + экспорт |
| **Пакетный** | CSV-файл (`id,text`) | Сводка по отзывам + топ-аспекты + разбивка + экспорт |

### 2.2. Одиночный режим

- **FR-1.1.** Ввод текста произвольной длины (до ~300-400 слов, ограничение модели).
- **FR-1.2.** Кнопка «Анализировать» запускает обработку.
- **FR-1.3.** Результат содержит:
  - Сводку: общий вердикт, количество позитивных/негативных/нейтральных аспектов, прогресс-бар.
  - Карточки аспектов: название, тональность, уверенность (%), контекст.
- **FR-1.4.** Кнопка «Скачать отчёт (HTML)» генерирует автономный HTML-файл со всей статистикой.

### 2.3. Пакетный режим

- **FR-2.1.** Загрузка CSV-файла формата `id,text` (без заголовков, UTF-8, максимум 5 МБ).
- **FR-2.2.** Валидация CSV:
  - Проверка наличия ≥2 колонок в каждой строке.
  - Проверка непустого текста.
  - Ошибки собираются и отображаются пользователю (первые 5 + счётчик остальных).
- **FR-2.3.** Превью первых 3 отзывов после загрузки.
- **FR-2.4.** Кнопка «Обработать» запускает пакетный анализ.
- **FR-2.5.** Прогресс-бар отображает:
  - Текущий отзыв (`Обработка отзыва N из M (#id)`).
  - Процент выполнения.
- **FR-2.6.** Кнопка «Пауза» приостанавливает обработку; повторный клик возобновляет.
- **FR-2.7.** Кнопка «Отменить» прерывает обработку; уже обработанные отзывы сохраняются.
- **FR-2.8.** После завершения:
  - **Сводка по отзывам:** сколько позитивных, негативных, смешанных.
  - **Топ-5 аспектов** с преобладающей тональностью.
  - **Разбивка по отзывам:** карточка на каждый отзыв с вердиктом, текстом и списком аспектов.
- **FR-2.9.** Кнопка «Скачать отчёт (HTML)» генерирует автономный отчёт.

### 2.4. Экспорт отчёта

- **FR-3.1.** Экспорт в HTML (автономный файл со встроенными стилями).
- **FR-3.2.** Содержимое отчёта зависит от режима:
  - **Одиночный:** сводка по аспектам, прогресс-бар, карточки аспектов.
  - **Пакетный:** сводка по отзывам, прогресс-бар, топ-аспекты, карточки отзывов.
- **FR-3.3.** Имя файла: `moodmapper_report_{mode}_{YYYYMMDD_HHMMSS}.html`.

### 2.5. Скачивание шаблона CSV

- **FR-4.1.** Кнопка «Скачать шаблон» генерирует CSV с 5 примерами.

## 3. Нефункциональные требования

- **NFR-1.** Работа **без серверной части** — всё в браузере.
- **NFR-2.** Поддержка современных браузеров с WebAssembly (Chrome, Firefox, Edge).
- **NFR-3.** Первая загрузка модели — до 60 секунд, последующие — из кэша.
- **NFR-4.** Скорость анализа: 2-5 секунд на отзыв.
- **NFR-5.** Максимальный размер CSV — 5 МБ.
- **NFR-6.** Русскоязычный интерфейс.

## 5. Алгоритм анализа

### Шаг 1: Поиск аспектов

Вход: текст отзыва.
Метод: поиск вхождений слов из словаря `ASPECTS` через `str.find()` с учётом регистра.
Выход: список `{word, start, end, aspect}`.

### Шаг 2: Выбор контекста

Для каждого аспекта:
1. Разбить текст на предложения по `.!?`
2. Найти предложение, содержащее аспект
3. Разбить предложение по тире (`—`, `–`, `-`)
4. Разбить по союзам (`но`, `однако`, `хотя`, `зато`, `и`, `а`, `да`, `а также`, `плюс`, `к тому же`, `при этом`)
5. Для кусков с >1 аспектом — разбить по запятым
6. Вернуть минимальный кусок, содержащий аспект

### Шаг 3: Анализ тональности

Вход: контекст.
Модель: `pipeline('sentiment-analysis', 'Artemeey2/rubert-base-cased-sentiment-onnx')`.
Выход: `[{'label': 'POSITIVE'|'NEGATIVE'|'NEUTRAL', 'score': float}]`.

Функция `normalize_sentiment` приводит метку к одному из трёх значений.

### Шаг 4: Постобработка маркерами

Вычисляется вес позитива и негатива:
- Каждый найденный маркер = **+1 к весу**
- Отрицание позитива (`не вкусно`) = **+2 к весу негатива**
- Усилитель рядом с маркером (`очень вкусно`) = **+1 к весу**

Логика корректировки:
- `NEUTRAL` + перевес негатива → `NEGATIVE`
- `NEUTRAL` + перевес позитива → `POSITIVE`
- `POSITIVE` + негативных больше → `NEGATIVE`
- `NEGATIVE` + позитивных больше → `POSITIVE`

### Шаг 5: Агрегация

**По аспектам:** количество позитивных, негативных, нейтральных; проценты.

**По отзывам (пакетный режим):**
- Группировка по `review_id`.
- Вердикт отзыва = по большинству аспектов:
  - 2 позитивных, 1 негативный → `POSITIVE`
  - 1 позитивный, 2 негативных → `NEGATIVE`
  - 1 позитивный, 1 негативный → `MIXED`

## 6. Формат данных

### 6.1. CSV для импорта

```csv
1,"Пицца была вкусной, но доставка опоздала на час"
2,"Обслуживание ужасное, больше не приду"
3,"Атмосфера приятная, музыка тихая, еда вкусная"
```

- Кодировка: UTF-8
- Разделитель: запятая
- Заголовки: отсутствуют
- Колонки: id, text
- Кавычки: обязательны, если текст содержит запятые

### 6.2. Внутренняя структура результата
```
{
    'review_id': '1',           # только в пакетном режиме
    'aspect': 'пицца',          # найденный аспект
    'sentiment': 'POSITIVE',    # финальная тональность
    'score': 0.66,              # уверенность модели
    'context': 'Пицца была вкусной,'
}
```
